# Доставка без патчинга репозиториев — обязательные требования

Дата: 2026-11-03. Источник: прямое требование владельца — «ревью кит в клауде код, кодекс и прочие системы должен доставляться без постоянного патчинга их; нужна ссылка на то, что меняется версионно, чтобы не менять конфиги этих агентов каждый раз».

**Статус: реализовано и выпущено в 0.28.0.** Документ фиксирует требования и доказательства; он написан после реализации, поэтому каждое требование ссылается на уже существующую проверку.

## VR-01. Версия выпуска не входит в файл, установленный в репозиторий

Файл `.githooks/pre-commit` в любом репозитории содержит только идентификатор *формата* хука и дайджест собственного тела. Номер версии кита в нём отсутствовать обязан. Причина: файл лежит в 80+ репозиториях, и версия в нём превращает каждый выпуск в правку чужого рабочего дерева.

Следствие, которое требуется доказывать, а не декларировать: выпуск, не изменивший тело хука, оставляет установленный файл побайтово тем же, поэтому повторная синхронизация ничего не пишет.

## VR-02. Хук, установленный прежними выпусками, остаётся «нашим»

Хук с маркером прежнего вида (`# omp-reviewer-kit hook vX.Y.Z body-sha256:…`) распознаётся как принадлежащий киту по дайджесту тела, а не по номеру версии:

- чтение формата возвращает `0` — самый старый формат;
- владение подтверждается совпадением дайджеста;
- ближайшая синхронизация заменяет его на текущий формат ровно один раз;
- хук, отредактированный после установки, остаётся чужим и не перезаписывается (конфликт, а не миграция).

## VR-03. Один вход доставки, без шагов по репозиториям

Обновление хостов выполняется одной командой `node scripts/deliver.mjs`:

- OMP обновляется через маркетплейс **только для этого плагина**; чужие плагины команда не трогает;
- Claude Code обновляется через свой маркетплейс;
- проверяется инвариант VR-01 на поставляемом шаблоне;
- шага «пройти по репозиториям» в команде нет, и его отсутствие проверяется, а не предполагается.

## VR-04. Установленный, но не отвечающий хост — провал, отсутствующий — пропуск

Если исполняемый файл хоста отсутствует, доставка сообщает «не установлен» и продолжает. Если файл есть, но `--version` или обновление завершились ошибкой, доставка обязана вернуть ненулевой код: молчаливый «пропуск» сломанного хоста запрещён.

## VR-05. Инвариант проверяется по форме, а не по текущей версии

Проверка «шаблон хука не несёт версию выпуска» обязана срабатывать на маркер любой версии, включая прошлые, а не только на номер собираемого выпуска. Иначе доставка пройдёт с устаревшим шаблоном.

## VR-06. Миграция выполняется один раз и не повторяется

Переход парка репозиториев на формат-маркер — одноразовая операция. После неё повторный запуск синхронизации на тех же байтах не пишет ни одного файла. Это свойство обязательно для любого выпуска: иначе VR-01 не выполнен.

## Вне области

- Публикация в npm (политика репозитория: плагин не распространяется через npm).
- Автообновление Claude Code, отключённое владельцем глобально.
- Замена загрузчика `templates/review-kit/run-review.mjs`: он уже не содержит версии выпуска и не участвует в проблеме.
