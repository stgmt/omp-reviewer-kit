# DESIGN — slop-v2: варианты реализации для каждого TAKE-требования

> Каждый пункт: требование → варианты с плюсами/минусами → паттерн/антипаттерн → рекомендация.
> OMP API: `pi.on('tool_call')` — CAN block (hook API, file-based .ts); `pi.on('tool_execution_*')` — observe-only (extension API).
> Источник: `~/.omp/plugins/node_modules/@oh-my-pi/pi-coding-agent/src/extensibility/hooks/types.ts` + `shared-events.ts`.

## D1. Compliance-гейт на write/edit тест-файлов (FR-D1 + FR-A1)

**Задача:** при write/edit тест-файла проверять 9 антипаттернов и блокировать/предупреждать.

| Вариант | Механизм | Плюсы | Минусы |
|---------|----------|-------|--------|
| **D1a** | OMP hook `pi.on('tool_call')` → `{block: true, reason}` | Детерминистический блок **до записи**; LLM видит reason и исправляет; fail-closed; zero-dep | Hook — file-based, не plugin; нужна установка в `.omp/hooks/`; нет встроенного anti-loop |
| **D1b** | Extension `pi.on('tool_execution_start')` → warn | Уже в extension.mjs — нет новой установки; LLM видит warning | **Не блокирует** — файл уже записан; advisory-only; легко игнорировать |
| **D1c** | Pre-commit hook | Уже есть инфраструктура; блокирует коммит | Поздно — файл уже написан и отредактирован; не ловит промежуточные состояния |
| **D1d** | Review-stage detector | Не нужен hook вообще | Самый поздний сигнал; не предотвращает, только находит |

| Паттерн | Антипаттерн | Почему |
|---------|-------------|--------|
| **D1a hook block** — блок до записи, LLM исправляет | **D1b extension warn** — файл уже записан, warning игнорируется | Блок до записи = единственный способ предотвратить плохой тест. Warning после записи = «уже сделано, лень переделывать». |
| **D1a hook block** — детерминистический, fail-closed | **D1d review-stage** — находит на review, не предотвращает | Review находит проблему когда она уже в diff. Hook предотвращает её появление. Разница между «не дать написать» и «найти после написания». |
| **D1c pre-commit** — блокирует коммит, не запись | **D1b extension warn** — advisory-only, нет enforcement | Pre-commit — последний рубеж, но не первый. Hook — первый рубеж. Оба нужны, но hook важнее. |

**Решение владельца (2026-09-21): D1c** — pre-commit gate, см. DEC-1. Автор рекомендовал D1a (блок до записи), владелец выбрал коммит: без установки перехватчика, на готовой pre-commit-инфраструктуре.

## D2. slop-test-hunter агент (FR-C1)

**Задача:** специалист, который ищет дефекты качества тестов в staged diff.

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **D2a** Новый агент `agents/slop-test-hunter.md` | Изолированный контракт; отдельная экспертиза; параллельно с risk-hunter; можно настроить model/tools | +1 агент; нужен spawns-allowlist в orchestrator |
| **D2b** Расширить `review-risk-hunter` — добавить lane `test-quality` | Не нужен новый агент; один hunter покрывает всё | Размывает фокус; test-quality — отдельная экспертиза; сложнее промпт |
| **D2c** Skill-only — `skills/test-slop/` с детекторами | Минимум кода; детекторы — чистые regex | Нет LLM-анализа; не ловит семантические проблемы (тавтология, fake-positive) |

| Паттерн | Антипаттерн | Почему |
|---------|-------------|--------|
| **D2a новый агент** — изолированный контракт, чёткий скоуп | **D2b расширить risk-hunter** — размывает фокус, смешивает экспертизы | Test-quality — отдельная экспертиза: weak assertion, fake-green, fixture-fake. Risk-hunter ищет correctness/security баги. Разные линзы, разные промпты, разные модели. |
| **D2a новый агент** — можно настроить model/tools отдельно | **D2c skill-only** — нет LLM, только regex | Regex ловит синтаксис (`toBeDefined`), но не семантику (тавтология: `expect(x).toBe(x)`). Нужен LLM для семантического анализа. |

**Рекомендация: D2a** — отдельный агент с чётким контрактом.

## D3. verify-kill.mjs (FR-B1 + FR-B2)

**Задача:** детерминистический kill-proof для тестов и детекторов.

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **D3a** Standalone `scripts/verify-kill.mjs` | Прямой порт verify-kill.ts; zero-dep; вызывается из любого места | Ручной вызов; не интегрирован в pipeline |
| **D3b** Интегрировать в review pipeline — verifier вызывает verify-kill | Автоматический kill-proof для каждого нового теста в diff | Сложнее; нужен парсинг diff → test file → mutation point; медленнее |
| **D3c** Slash command `/reviewer-kit:verify-kill` | Явный вызов; интегрирован в extension | Ручной; не автоматический |

| Паттерн | Антипаттерн | Почему |
|---------|-------------|--------|
| **D3a standalone** — простой, переиспользуемый, testable | **D3b integrated** — сложный, медленный, fragile | Standalone — один скрипт, один вход, один выход. Integrated — нужен diff parser, mutation point finder, timeout handling. Сложность растёт, польза — marginal. |
| **D3a standalone** — вызывается из test-author и из review | **D3c slash-command** — ручной, не автоматический | Slash-command — для пользователя. Standalone — для агента и для pipeline. Разные аудитории. |

**Рекомендация: D3a** — standalone script, вызываемый из test-author и из review pipeline.

## D4. Anti-loop маркеры (FR-D7)

**Задача:** каждый блокирующий гейт должен иметь hash+cooldown+maxRetries.

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **D4a** Shared `src/infra/marker-utils.mjs` | Единый паттерн; тестируемо; DRY; один формат маркера | +1 модуль; нужна интеграция в каждый гейт |
| **D4b** Inline в каждом гейте | Нет shared dependency | Дублирование; легко забыть; разные реализации; разные форматы |

| Паттерн | Антипаттерн | Почему |
|---------|-------------|--------|
| **D4a shared module** — единый формат, единая логика | **D4b inline** — дублирование, разные форматы, легко забыть | Anti-loop — обязательный инвариант, не опциональный. Shared module гарантирует что каждый гейт использует один и тот же формат и одну и ту же логику. Inline — каждый гейт реализует по-своему, легко забыть cooldown или maxRetries. |

**Рекомендация: D4a** — shared module. Anti-loop — обязательный инвариант.

## D5. Escape-hatch аудит (FR-D8)

**Задача:** `[skip-X: reason≥8]` → JSONL; reason <8 chars → warning.

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **D5a** Единый `audit-reports/escapes.jsonl` | Единый формат; читается stumble-отчётом; аудируемо; уже есть `audit-reports/` | +1 модуль |
| **D5b** Per-gate escape-логи | Независимость гейтов | Разрозненные логи; сложнее stumble-отчёт; разные форматы |

| Паттерн | Антипаттерн | Почему |
|---------|-------------|--------|
| **D5a unified log** — единый формат, единое место | **D5b per-gate** — разрозненные логи, разные форматы | Stumble-отчёт должен читать все escapes из одного места. Per-gate — нужно сканировать N файлов, парсить N форматов. Unified — один файл, один формат, один запрос. |

**Рекомендация: D5a** — единый лог. Уже есть `audit-reports/` директория.

## D6. Stumble-отчёт (FR-E5)

**Задача:** единая панель по escape-логам + последний прогон + pending + ошибки → 🟢/🟡.

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **D6a** Расширить `/reviewer-kit:status` | Уже есть команда; естественное место; observability — часть здоровья | Раздувает status; смешивает review-status и observability |
| **D6b** Новая команда `/reviewer-kit:observe` | Отдельная команда; чистый скоуп | +1 команда; пользователь должен знать о ней |

| Паттерн | Антипаттерн | Почему |
|---------|-------------|--------|
| **D6a extend status** — observability в существующей команде | **D6b new command** — +1 команда, пользователь не знает | Status — естественное место для «здоровья системы». Escapes, last-run, pending — это здоровье. Новая команда — пользователь должен знать что она есть и когда её вызывать. |

**Рекомендация: D6a** — расширить status.

## D7. Dogfood-паттерн (FR-E6)

**Задача:** drive каждый tool/hook против реальных данных, записывать что реально возвращает.

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **D7a** Skill-процедура `skills/dogfood/SKILL.md` | Доктрина; агент следует процедуре; минимум кода | Не автоматизировано; зависит от агента |
| **D7b** Автоматический `scripts/dogfood.mjs` | Автоматизировано; воспроизводимо; CI-friendly | Нужны fixture-входы; сложнее; нужен runner |

| Паттерн | Антипаттерн | Почему |
|---------|-------------|--------|
| **D7a skill-procedure** — доктрина, агент следует | **D7b automated script** — нужны fixtures, сложнее | Dogfood — процедура, не скрипт. Агент должен понимать *почему* он вызывает tool с реальным входом, а не просто запускать скрипт. Автоматизация — отдельная фича, не часть v2. |

**Рекомендация: D7a** — skill-процедура для v2. D7b — отдельная фича.

## Сводка: паттерн vs антипаттерн

| Пункт | Паттерн | Антипаттерн | Почему паттерн лучше |
|-------|---------|-------------|---------------------|
| D1 | Hook block до записи | Extension warn после записи | Блок предотвращает, warn — уже сделано |
| D2 | Новый агент с изолированным контрактом | Расширить risk-hunter | Test-quality — отдельная экспертиза |
| D3 | Standalone script | Integrated в pipeline | Простота + переиспользуемость |
| D4 | Shared marker-utils | Inline per-gate | Обязательный инвариант, DRY |
| D5 | Unified escapes.jsonl | Per-gate логи | Единый формат, единое место |
| D6 | Extend /status | New /observe | Observability — часть здоровья |
| D7 | Skill-процедура | Automated script | Доктрина для v2, автоматизация — отдельная фича |
| D8 | Новый агент | Skill-only | NEVER flip first — инвариант, требующий изоляции |
| D9 | Новый test-slop skill | Extend reality-first | Отдельная линза, не часть review |

## Принятые решения (2026-09-21, владелец)

Решения зафиксированы со слов владельца. Реализация — одна волна: TASK-1..TASK-10, фаза Wave 1.

## DEC-1: D1 → pre-commit gate (D1c)

- **Rationale:** гейт на коммите не требует установки перехватчика и переиспользует готовую pre-commit-инфраструктуру reviewer-kit; решение владельца.
- **Trade-off:** поздний сигнал — плохой тест уже написан и лежит в рабочей копии; промежуточные состояния не ловятся. Компенсация: fail-fast до LLM-ревью, не жжёт токены.
- **Alternatives:** D1a hook block — отклонён (требует установки, владелец выбрал коммит); D1b extension warn — отклонён (advisory-only, нет enforcement); D1d review-stage — оставлен вторым слоем через slop-test-hunter, не гейт.

## DEC-2: отдельные агенты и скиллы (D2a, D8a, D9b)

- **Rationale:** test-quality — отдельная экспертиза; изолированные контракты; решение владельца.
- **Trade-off:** больше файлов (2 агента + 1 скилл), нужен spawns-allowlist в оркестраторе.
- **Alternatives:** расширить review-risk-hunter — отклонено (размывает фокус); skill-only — отклонён (нет LLM-анализа семантики).

## DEC-3: verify-kill — standalone script (D3a)

- **Rationale:** один вход, один выход, вызывается из test-author и вручную; рекомендация автора спеки, возражений не было.
- **Trade-off:** не автоматический в pipeline; интеграция — отдельная работа.
- **Alternatives:** интеграция в review pipeline — отклонена (нужен diff-парсер и поиск точек мутации, польза marginal); slash-command — не нужен (скрипт покрывает).

## DEC-4: D4–D7 по рекомендации автора (без возражений)

- **Rationale:** shared marker-utils (D4a), единый escapes.jsonl (D5a), расширить reviewer-kit status (D6a), dogfood как skill-процедура (D7a).
- **Trade-off:** нет — варианты-антипаттерны слабее по DRY и аудируемости, см. таблицу выше.
- **Alternatives:** inline-маркеры, per-gate логи, новая команда observe, скрипт dogfood — все отклонены (см. «Почему» в таблице).

## DEC-5: scope — одна волна, все 20 TAKE

- **Rationale:** решение владельца: делать всё сразу, предварительно прописав в спеке.
- **Trade-off:** большая волна (10 задач); дольше до первого результата, чем при поэтапном подходе.
- **Alternatives:** три этапа detectors → gates → agents — отклонены владельцем.
